# 小红书 文风简报

> 为 aghub（One hub for every AI coding agent）在小红书的宣发文案调研。
> 调研方法：5 轮 WebSearch（中文为主）+ WebFetch 抓取爆文拆解 / 程序员副业实战 / 去 AI 味方法论页面。
> 标注约定：[检索所得] = 有页面来源支撑；[经验推断] = 结合小红书社区文化与开发者赛道现状补足，无直接爆款原文佐证。

---

## 原生语感（这里的人到底怎么说话、什么调性）

小红书的母语是「朋友私聊安利」，不是「产品发布会」。默认第一人称、口语、带情绪波动——「谁懂啊」「救命」「绝了」「我真的会谢」「一整个爱住」「听劝」是这套语言的语气词底座 [检索所得]。它容不下「综上所述」「本工具旨在」这种书面/官腔句式，一出现就被判定成营销号或 AI 稿 [检索所得]。

调性上它偏「生活化的实用主义」：哪怕讲的是硬核工具，也要落到「我被什么烦到了 → 我找到了什么 → 现在爽在哪」的个人叙事里。程序员/效率赛道在小红书能成立，靠的是把技术专长交叉到「效率/省时间/少踩坑」这类人人有共鸣的痛点上，而不是秀技术本身 [检索所得]。一句话：这里奖励「真诚地显摆一个好东西」，惩罚「一本正经地介绍一个产品」。

## 什么内容能起量（越具体越好）

- **痛点开局 + 数字收口的标题**：「痛点+解决方案」或「数字+干货」是效率赛道最稳的两个模板，例：「告别加班！5 个 Python 自动化脚本解放你的双手」「0 基础学编程？我只推荐这 3 本书」[检索所得]。
- **封面即标题**：封面用大字报直接把「效果词 + 适用人群」怼上去，首页双列信息流里靠封面文案决定点不点进来 [检索所得]。开发者工具尤其吃「界面截图好看 + 一句扎心痛点压字」。
- **图文 5-9 张、一图一知识点**：每张图承载一个点，排版留白清晰、别堆字；封面外最多 9 张图 [检索所得]。
- **测评/对比/合集结构**：「N 个 XXX 神器」「我的电脑必装 X 个软件」这类合集与横评天然高收藏，用户对「干货/避雷/测评」三类内容最敏感 [检索所得]。
- **专攻一点，别面面俱到**：一篇只打 2-3 个核心卖点，比样样都讲更容易爆 [检索所得]。
- **真实截图 / 真人体验感**：口语化亲身描述 + 场景化用法 + 前后对比，比参数罗列有说服力 [检索所得]。
- **发布时机**：工作日中午 12-13 点、晚 19-21 点数据较好 [检索所得]。
- **「省了多少时间/少配了多少次」的可感收益**：开发者受众吃「量化的解脱感」，比「功能强大」有效得多 [经验推断]。

## 什么显 AI 味 / 显尬 / 显硬广（要避开的雷）

- **书面官腔词**：「综上所述」「总而言之」「本工具旨在」「首先/其次/再次」——AI 稿最大特征就是爱下定义、爱分条总结、爱工整过渡 [检索所得]。
- **太完美、没瑕疵、没情绪**：全篇书面语、零口语瑕疵、零真实感受，会被判定 AI 生成，平台甚至会打「疑似 AI」标降流 [检索所得]。
- **长句 + 空洞形容词**：超过 20 字的长句、「高效便捷、功能全面」这种空词堆砌，是硬广味来源 [检索所得]。
- **直接放二维码 / 微信 / 下载链接**：前期直接打广告、贴引流方式违规且压流量，得靠谐音、拼音、评论区引导 [检索所得]。
- **人设跑偏**：内容风格和账号定位不符会被限流 [检索所得]。
- **术语轰炸**：满屏 MCP / adapter / keychain / SHA-256 直接糊脸，会把非重度用户劝退——术语要么翻译成人话，要么只对精准受众放 [经验推断]。
- **一看就是官方号口吻**：小红书对「品牌自卖自夸」容忍度低，第一人称踩坑故事的转化远好于第三人称产品介绍 [经验推断]。

## 格式与硬约束（篇幅、标题、标签、封面、结构、发布机制）

- **标题**：≤20 字最稳，核心关键词塞进前 10 个字；数字/痛点/悬念三选一或组合 [检索所得]。
- **封面**：竖版 3:4（约 1242×1660px），首页双列更显眼；大字报文案 + 好看的产品/界面截图；模糊封面会被判低质不推 [检索所得]。
- **图片数**：连封面最多 9 张，建议 5-9 张，一图一点 [检索所得]。
- **正文排版**：小红书原生编辑器没有排版能力（连空行都要手动），所以靠 **emoji 当分隔符/小标题** + 短句 + 空行撑起可读性 [检索所得]。emoji 别当图标乱撒，用在分点和情绪强调（✨❗🔥✅）。
- **标签**：单篇 **3-5 个**为宜，优先挂 50 万+讨论量的话题词，匹配度越高越好推；标签类型分自定义/品牌/商品/地点等 [检索所得]。
- **正文结构（效率工具通用骨架）**[检索所得+经验推断]：
  1. 钩子：一句扎心痛点 / 反常识结论（前 3 行决定完读率）
  2. 「我之前有多烦」：具体场景 + 情绪
  3. 「我发现了 X」：自然带出工具，别急着报参数
  4. 分点讲 2-3 个爽点，每点配一张截图
  5. 收尾：适用人群 + 一句真诚的「你们也试试」+ 3-5 标签
- **发布机制**：CES 综合分（点赞/收藏/评论/转发/关注）决定推荐量，收藏权重对干货类尤其高——要在结尾主动引导「先收藏再慢慢配」[检索所得]。

## 自我推广的容忍度与原生包装方式

小红书对「硬广」容忍度低，但对「独立开发者真诚安利自己做的东西」有天然好感——这是它区别于纯商业平台的地方。检索到的一个明确信号：独立开发者常用「**我做了一个 XXX 小工具，免费试用**」作为冷启动标题，很多人的第一批用户就是从小红书/即刻来的 [检索所得]。

能直接说「我做的」，但不能用官方口吻卖。原生包装的关键是**把「我做了个工具」讲成「我被一个问题烦到自己动手解决了」**：
- 主角是「我遇到的痛点」，工具是解药，不是主语。
- 用踩坑/折腾过程换信任：先讲你试过哪些别的方案都不行，再引出自己做的。
- 免费 / 开源 / 不割韭菜的信息前置，能显著降低戒心（开源在这个赛道是加分项）[经验推断]。
- 引流走评论区和主页简介，正文不硬塞链接 [检索所得]。

档位建议：**能自称「我做的」，但每篇只露一次，且必须包在个人故事里。** 别开小号刷、别第三人称吹。

## 3-4 个原生开头钩子示例（开发者工具，可直接借用）

> 均按小红书口语腔写，第一人称、痛点开局、前 3 行抓人。[经验推断，句式骨架来自检索所得的爆文模板]

1. **痛点直球型**
   「谁懂啊……我电脑上装了 5 个 AI 编程工具，MCP 配置来回复制粘贴了 8 遍😭 直到我自己写了个东西一键同步」

2. **反常识结论型**
   「用了 Cursor 又用 Claude Code 的姐妹听我一句：别再一家家配了。这些 key 和 skill 其实能一次搞定，我踩了半年坑才明白」

3. **量化解脱型**
   「以前换一个 AI coding agent 要重配半小时，现在 30 秒。分享我做的这个小工具，纯免费还开源✨」

4. **场景共鸣型**
   「打工人 coding 现状：Claude、Codex、Copilot 全开，配置各写各的，换台电脑全废。我实在受够了，于是……」

## 真诚⇄炒作该落在第几档

**2 档（偏真诚克制，允许一点封面标题党）。**

理由：小红书的算法要「痛点+好封面+情绪钩子」才有点击，纯 0 炒作（1 档）在双列信息流里根本没人点；但这个平台对硬吹和 AI 味的惩罚极重，一旦语感失真直接判营销号降流。Flacier 的独立开发者气质在这里是稀缺资产，「我自己被烦到才做的、免费开源」的真诚叙事本身就是最好的钩子。所以标题封面可以适度标题党（数字、痛点词、「谁懂」），但正文必须真人口语、有折腾过程、不吹参数——把炒作留在封面，把真诚留在正文。

## aghub 在这个平台的切入角度

**角度一：多 agent 用户的「配置地狱」痛点（主推，最普世）**
- 选题：把「重复配置 MCP/skill/key」的日常折腾拍成痛点，工具做解药。
- 标题示例：「装了 8 个 AI 编程工具后，我终于受不了自己写了个配置管家🧰」
- 封面大字报：「一次配置，同步到所有 AI coding agent」+ 一张干净的桌面 App 截图。
- 正文骨架：吐槽 5 个 agent 各配各的 → 展示一次配好 MCP 全同步 → skill 跨 agent 共享 → 结尾「免费开源，评论区蹲需求」。

**角度二：BYOM / 用量监控的「省钱+安全」子选题（打精准重度用户）**
- 选题：每个 agent 单独选模型 + key 存系统钥匙串 + Claude/Codex 用量监控，切「怕超支、怕 key 泄露」的焦虑。
- 标题示例：「AI 编程一个月烧多少钱？我做了个能跨 agent 看用量、还把 key 锁进钥匙串的工具」
- 适合作为系列第二篇，承接角度一沉淀下来的精准粉。
