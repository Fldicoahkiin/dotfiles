## 原生语感（这里的人到底怎么说话、什么调性）

X 的独立开发者圈（#buildinpublic / indie hacker）说话是「第一人称、当下进行时、口语、短句」。不是新闻稿的「We are excited to announce」，而是「I just shipped X」「been building this for 3 months, finally live」。句子短，一行一个意思，动词开头，标点少。真诚和自嘲能加分——晒进度也晒翻车（"lost a full day to a dumb bug"），社区对「highlight reel（只报喜的精修集锦）」免疫，对「behind-the-scenes（幕后真实过程）」买账 `[检索所得]`。

调性光谱上，开发者受众「一闻到营销味就跑」（sniff out anything promotional），所以原生腔是「我做了个东西解决我自己的痛点，顺手分享」，而不是「向您隆重介绍」。语言层面：英文是主场，中文出海开发者绝大多数用英文发 launch，中文只在面向华语社区的番外内容里用 `[经验推断]`。

## 什么内容能起量（越具体越好）

- **原生视频 / 演示 GIF 是硬通货**：native video「比纯文字帖多约 10x 互动」，带图/GIF 也有明显加成，纯文字无加成也无惩罚 `[检索所得]`。对开发者工具，一条 15–40 秒的「装上→敲一条命令→出结果」录屏顶十行文字。
- **「我踩了个坑 / 我犯了个错」类**：`"I made a $X mistake this week..."`、`"lost a day to..."` 这类开头起量，因为它反营销、显真实 `[检索所得]`。
- **复盘 thread（learnings）是涨粉最快的形态**：`"7 things I learned going from $0 to $5K MRR"` 这类能到 5 万+ 曝光、200+ 新粉 `[检索所得]`。thread 比等价单推「总互动多约 3x」，且「引发主页访问概率高 60%」，还会被 Google/X 搜索收录，寿命更长 `[检索所得]`。
- **具体数字 / 具体功能名 > 泛泛而谈**：`"signup to first value in under 2 minutes"` 胜过 `"making good progress"`。具体本身就是可信度 `[检索所得]`。
- **「一次配置，全部生效」这种可视化对比**：before/after、一个动作波及多处的演示，天生适合 GIF，dwell time（停留时长）高。
- **发布时机**：算法「盯前 30–60 分钟」，前一小时的互动速度决定后续扩散；面向美国受众，北京时间晚 9 点到凌晨 3 点是窗口 `[检索所得]`。
- **互动权重**（相对 like=1x）：reply=27x、retweet=20x、quote=25x、bookmark=10x，而「作者回复了某条 reply，那条 reply」高达 150x——所以发完蹲评论区、认真回复，是算法层面的杠杆 `[检索所得]`。

## 什么显 AI 味 / 显尬 / 显硬广（要避开的雷）

- **新闻稿腔**：「We're thrilled/excited to announce」「Introducing the powerful, all-in-one solution」——一眼公关文，开发者直接划走 `[经验推断]`。（注：用户全局规则也禁 powerful / seamless / robust 这类词，正好和平台反感一致。）
- **正文里放外链**：自 2026-03 起，非 Premium 账号带外链的帖「中位互动近乎为零」，算法主动压制以留住用户。规矩是**正文只放价值内容，链接放到第一条 reply** `[检索所得]`。
- **堆标签**：5 个以上 hashtag 触发压制；#buildinpublic 之类点到一两个即可，别做成标签墙 `[检索所得]`。
- **humble brag（凡尔赛）**：用抱怨/谦虚包装的自夸，研究显示比直接自夸更招人烦。要晒成就就大方直接晒，别「哎呀没想到这么多人 star 真不好意思」`[检索所得]`。
- **只广播不互动 / 定时轰炸**：「5 分钟发 10 条」被判 engagement farming 压制；纯 broadcast 不回评论也起不来 `[检索所得]`。
- **0 粉丝空降 launch 期待爆红**：几乎不存在。没有前期积累的 launch 就是「发给几个朋友和 bot，拿到十个注册」的结局——launch 不是一天，是一段持续讲述的故事 `[检索所得]`。
- **通用无信息量的漂亮话**：low-effort generic content 被降权 `[检索所得]`。

## 格式与硬约束（篇幅、标题、标签、封面、结构、发布机制）

- **单推 vs thread**：
  - **单推**：适合「一句强观点 / 一个惊人事实 / 一个演示 GIF」，能 10 秒内读完的最好。punchy 优先 `[检索所得]`。
  - **thread**：适合 launch 和复盘。经典 launch thread 结构 = ①钩子推（痛点或成果，配演示视频/GIF，**不放链接**）→ ②这是什么 / 为什么做 → ③怎么用（分点或短演示）→ ④给谁用 / 现在能拿到 → 收尾软 CTA + **链接放这条或首条 reply** `[检索所得] + [经验推断]`。
- **第一条推是命根子**：整条 thread 能不能扩散，取决于首推前一小时的互动。首推必须自带钩子和视觉 `[检索所得]`。
- **链接机制**：正文零链接，链接放 reply（见上）`[检索所得]`。
- **封面/媒体**：launch 首推建议配「装上就能跑」的短视频或 GIF；截图次之；纯文字首推起量最难 `[检索所得]`。
- **时间衰减**：帖子可见度约每 6 小时减半，24 小时后基本无分发；所以要挑窗口发、发完蹲评论 `[检索所得]`。
- **节奏**：build-in-public 的推荐日常是「每天 2–3 条（1 条进度 + 1–2 条价值/互动）」，每周日或周一发一条复盘 thread `[检索所得]`。launch 不是孤立一天，可以铺成多日的「launch week」叙事 `[检索所得]`。

## 自我推广的容忍度与原生包装方式

**能直接推广，但要遵守「80/20」**：80% 内容是价值/互动/幕后，20% 才是明着讲自己的产品 `[检索所得]`。X 独立开发者圈本身就是「看别人 build 产品」的地方，所以「我做了个工具」完全被接纳——前提是它读起来像**分享**而不是**投放**。

原生包装的关键动作：
- **从「我自己的痛点」讲起**，产品是这个痛点的解药，而不是从产品功能清单讲起。开发者对「解决真实痛点」的叙事天然有共鸣 `[检索所得]`。
- **软 CTA 藏在价值 thread 结尾**：`"If you found this useful, I built [X] that does exactly this"`——比开门见山打广告软得多 `[检索所得]`。
- **让数据/用户替你说话**：`"Got this message from a customer today..."` 配截图，比自夸可信；别人替你夸是最佳状态 `[检索所得]`。
- **过程即内容**：把配置痛点、取舍、翻车都摊开讲，「幕后感」本身就消解了广告味 `[检索所得]`。

## 3–4 个原生开头钩子示例（针对开发者工具，X 母语腔，可直接借用）

> 均为按平台文风撰写的**模板**，非真实爆款原文 `[经验推断]`。

1. **痛点直击型**
   `I use 5 different AI coding agents. That's 5 places to re-add the same MCP server. 5 configs to keep in sync. I got tired of it, so I built one hub for all of them 👇`

2. **翻车/自嘲型**
   `Spent an embarrassing amount of time last month copy-pasting the same skill into Cursor, Claude Code, and Codex. Never again. Here's the tool that fixed it for me:`

3. **反差数字型**
   `22 AI coding agents. 1 place to configure them. MCP servers, skills, models, keys — set once, ships everywhere. Quick demo 👇` （配 GIF）

4. **幕后过程型（thread 首推）**
   `Been quietly building this for a few months. It manages configs for every AI coding agent I use — Claude Code, Cursor, Codex, Gemini, 18 more. Open source, Rust + Tauri. Let me show you what it does 🧵`

---

## 真诚⇄炒作该落在第几档（1=最真诚克制 … 5=最放飞烂炒）

**建议落在第 2 档（偏真诚，带一点点节奏感）。**

理由：X 独立开发者圈对营销味的免疫是最强的平台之一（受众「一闻就跑」），Flacier 的真诚气质与之天然契合，硬炒作会反噬。但纯第 1 档（只闷头发日志、零钩子、零节奏）在这里起不来——launch 需要首推钩子、需要蹲评论、需要挑发布窗口，这些「运营动作」不算炒作，是平台的基本玩法。所以第 2 档：内容真诚、痛点真实、演示不注水，但**允许**精心设计首推钩子、铺 launch week 节奏、大方晒数据。别到第 3 档以上的「悬念营销 + 夸张形容词 + 情绪拉满」，那在开发者受众里减分。

## aghub 在这个平台的切入角度（结合背景给 1–2 个具体选题/标题）

**角度 A：痛点共鸣 + 演示 GIF 的 launch thread（主推荐）**
- 首推（配 15–30 秒 GIF：一次配好 MCP → 依次出现在多个 agent 里）：
  `Every AI coding agent wants its own config. Same MCP server, re-added 5 times. Same skill, copy-pasted everywhere. So I built aghub — set it once, it ships to all of them. 🧵`
- thread 分段：② 为什么做（我自己重度用 N 个 agent 的真实痛点）→ ③ 一次配置跨 agent 部署 MCP + 可移植 .skill 包 + 每 agent 独立选模型 + BYOM 密钥进 keychain → ④ 支持 22+ agent（Claude Code / Cursor / Codex / Gemini …）、Rust + Tauri、开源 → 收尾软 CTA，**GitHub 链接放这条或首条 reply**。

**角度 B：单推 + 强反差数字（配一张对比图或短 GIF，做日常曝光 / 预热）**
- 标题：`22 AI coding agents. 1 config. MCP servers, skills, models, keys — configure once, everywhere. Open source. Rust + Tauri.`（正文零链接，链接进 reply）
- 变体（复盘 thread 拉涨粉）：`I manage configs for 22 AI coding agents in one place now. Here are 5 things that broke my brain about how differently each agent stores MCP + skills 🧵`——把跨 agent 配置差异当成技术复盘讲，天然有信息量、可被搜索收录，还顺带带出 aghub。
