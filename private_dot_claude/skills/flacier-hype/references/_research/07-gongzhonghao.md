# 微信公众号 文风简报

> 面向 aghub（One hub for every AI coding agent）的平台文风库。
> 调研法：WebSearch 6 轮（中文为主）+ WebFetch 抓真实创作指南/复盘文。标注 [检索所得] / [经验推断]。
> 定位：次要平台、批量向；主打长文推送、克制版标题党、技术科普 + 个人故事、可复用博客长文改写。

---

## 原生语感（这里的人到底怎么说话、什么调性）

公众号技术长文的原生腔是「一个真人在跟你聊天，不是文档在朗读你」。[检索所得] 优质技术号的口吻普遍带自省和自嘲：直接承认「粉丝就是涨不上去，这一度让我有点迷惘」，用「摸鱼」「说白了」「但问题来了」这类口语替代学术腔，讲事情走时间线而不是走结论。调性是「痛点 → 我踩了坑 → 我怎么想的 → 给你一个可独立传播的判断」。[经验推断] 和 V2EX/Twitter 那种碎片吐槽不同，公众号读者是「点开就准备读 5 分钟」的心态，所以开头要给「阅读承诺」，中段要有小标题喂节奏，结尾要有一句能被转发的话。它比即刻端庄、比知乎口语、比 CSDN 有人味。

## 什么内容能起量（越具体越好）

- **横评/选型类**：[检索所得]「2026 年 AI 编程工具怎么选：Cursor / Claude Code / Codex / Windsurf / Zed 横评」是当下中文技术圈的持续热门题材（腾讯云、博客园、知乎均有高热长文）。aghub 天然站在这个题材的上游——它管的就是这 22 个 agent。
- **「我踩过的 N 个坑」复盘体**：[检索所得] 数字化 + 第一人称，如「从 0 到 X，我踩过的 5 个坑」，是技术号最稳的起量结构。
- **保姆级教程 / 折腾实录**：[检索所得]「自从用了 Claude Code…（保姆级安装教程）」这类标题在知乎/公众号反复出圈。手把手 + 截图 + 「跟着做就行」。
- **反常识判断**：[检索所得] 创作指南明确建议每篇留一句「XX 判断」——「明明是国产 AI，为什么反而不懂中文」这种反差冲撞。
- **热点借势**：[检索所得] 某工具涨价/发布/被封 → 蹭事件，如「Copilot 涨价 26 倍，AI 免费时代结束了」。
- **痛点共鸣开局**：[经验推断] 重度用多 agent 的人「受够了在每家工具里重配 MCP/skill/key」——这个痛点本身就是钩子，共鸣即转发。
- **数据/复盘透明**：[检索所得] 把真实数字摊开（阅读量、star 数、踩坑成本）比喊口号更能起量，读者信「敢晒数据的人」。

## 什么显 AI 味 / 显尬 / 显硬广（要避开的雷）

- [检索所得] **套话式开头**：「随着人工智能技术的发展」「近年来 AI 逐渐进入视野」——一秒暴露 AI 代笔，直接划走。
- [检索所得] **空洞黑话**：「赋能、闭环、生态、范式、打通」——技术读者的尬点雷区。
- [检索所得] **绝对化夸张**：「全网炸了」「彻底完了」「颠覆」——微信官方 2024 起持续治理标题党，混淆/煽动/夸大会被限流甚至处罚。
- [检索所得] **列表式复读总结**：结尾又把全文 bullet 复述一遍，是典型 AI 结构。
- [检索所得] **产品文档 / 广告式语气**：通篇「本工具支持 XX、具备 XX」的 feature 罗列，读者立刻识别为软文。
- [检索所得] **标题货不对板**：说「10 个技巧」正文只有 3 个 → 直接掉粉，破坏信任。
- [经验推断] **过度排比 + emoji 分点轰炸 + 每段都加粗**：新一代「AI 排版味」，比黑话更隐蔽但老读者一眼看穿。
- [经验推断] **全程无「我」**：没有第一人称经历、没有具体时间/数字/失败细节，只有正确的废话。

## 格式与硬约束（篇幅、标题、标签、封面、结构、发布机制）

- **群发机制**：[检索所得] 订阅号每天仅 1 次群发（0 点刷新，不累加），单次最多 8 篇。「直接发表」不占群发次数但不推送。→ aghub 批量向策略：攒够一波再发，别浪费当天唯一推送。
- **字数上限**：[检索所得] 正文上限 50000 字；标题最长 64 字；作者名 ≤8 字；摘要 ≤120 字（且最好别超手机一行）。
- **推荐篇幅**：[检索所得] 长文甜点区约 4500 字 ≈ 14 分钟阅读；每段 ≤3 行；每 300–500 字一个小标题；单句尽量短。
- **标题字数**：[检索所得] 15–32 个中文字符优先，最长 36；建议至少改 5 版（分别强化数字/情绪/反差/产品名/读者利益）。
- **封面**：[检索所得] 转发卡片取第一张图截图，比例 3:4 或 4:3（最佳 3:4，1080×1440px）；正文图宽 1080px、PNG-24 抗压缩、单图像素积 <600 万。
- **原创声明**：[检索所得] 原创内容标「原创」可获保护与推荐权重；转载/洗稿新号「必死无疑」（复盘文原话）。
- **长文结构模板**（[检索所得] 创作指南）：
  - 工具评测类：钩子 → 工具是什么 → 实际任务演示 → 优点 → 不足 → 适合人群 → 上手方法 → 互动结尾
  - 痛点避坑类：痛点 → 常见误区 → 踩坑原因 → 判断标准 → 具体清单 → 互动结尾
  - 开头 120 字须做完三件事：交代发生了什么 + 表达强烈情绪 + 抛出核心问题。

## 自我推广的容忍度与原生包装方式

**容忍度：中。** [经验推断] 公众号本质是「私域沉淀池」，读者默认作者会推自己的东西，比小红书宽容；但硬广（feature 罗列 + 下载链接）会被当软文划走。诀窍是**把「我做了个工具」讲成「我遇到一个问题，忍不了，于是自己写了个东西解决它」**——工具是故事的结果，不是文章的主语。

原生包装方式：
- **痛点前置法**：先花 1/3 篇幅把「多 agent 反复配置」的痛写透，读者点头「对对对就是这样」，工具出场时是「救星」而非「广告」。
- **横评顺带法**：写一篇 22 个 agent 的 MCP 配置横评/吐槽，aghub 只在「那有没有一次搞定的办法」处自然浮现，工具是横评的副产品。
- **踩坑复盘法**：讲「为了统一管理这些 agent 我折腾了多久、走了哪些弯路」，最后开源，读者买账的是过程不是产品。
- **开源人设兜底**：强调 Rust + Tauri + 开源、密钥进系统 keychain，用「我自己每天在用」而非「你应该用」。
- **克制 CTA**：文末一句「代码在 GitHub，链接放评论区/阅读原文」即可，别通篇导流。

## 3–4 个原生开头钩子示例（可直接借用）

> [经验推断] 均按创作指南「前 120 字 = 发生了什么 + 情绪 + 核心问题」写成，克制版标题党。

**钩子 A（痛点共鸣 + 自嘲）**
> 我电脑里装了 7 个 AI coding agent：Claude Code、Cursor、Codex、Windsurf……上周我加了一个新的 MCP server，然后发现——我得在这 7 个地方，把同一份配置手动抄 7 遍。抄到第 4 遍的时候我停下来问自己：这活儿，2026 年了，真的还得人干吗？

**钩子 B（横评切入 + 反常识）**
> 这两年 AI 编程工具横评满天飞，Cursor vs Claude Code vs Codex 吵得不可开交。但我发现一个没人聊的真相：真正重度的人根本不「二选一」，他们全都装。而全都装的代价，是每换一个工具，MCP、skill、模型、API key 就得重配一遍。今天不聊选谁，聊聊怎么让它们共用一套配置。

**钩子 C（数字 + 事件感）**
> 22 个 AI coding agent，22 套配置文件，22 个存 API key 的地方。这是我做 aghub 之前，桌面的真实状态。三个月后它变成了：一处配置，全部同步。这篇讲讲中间我踩过的坑，以及为什么最后我用 Rust 重写了它。

**钩子 D（故事 + 强判断）**
> 事情的起因很蠢：我在 Cursor 里配好的一个 skill，想在 Claude Code 里也用，结果发现两边格式完全不通，得手动搬。那一刻我冒出一个判断——**AI agent 之间缺的不是能力，是一个「配置中枢」。** 于是我花了三个月把这个中枢做出来了，开源，叫 aghub。

## 真诚⇄炒作该落在第几档

**建议：2 档（偏真诚克制，标题可摸到 3）。**

理由：[经验推断 + 检索所得]
- 公众号技术读者对「太用力」高度敏感，微信官方又在持续打击标题党，放飞（4–5 档）风险高、掉粉快。
- 但纯 1 档（技术文档式老实）在公众号的推荐机制里起不来——标题不吸引就没有点开，「90% 新号做不起来是标题问题」。
- 最优解是**正文 2 档的真诚（第一人称、晒数据、承认不足），标题 3 档的克制标题党（有数字、有情绪、有产品名，但不夸大不欺骗）**。即「货真价实的东西，配一个让人愿意点开的标题」。

## aghub 在这个平台的切入角度

**选题 1（横评上游 + 痛点，主推）**
- 角度：不站队某个 agent，而是站在「全都用」的重度用户视角，把「跨 agent 重复配置」的痛写成公共议题，aghub 作为解法自然收尾。
- 备选标题：
  - 《装了 7 个 AI 编程工具后，我受够了把同一份配置抄 7 遍》
  - 《AI 编程工具横评看腻了？真正的问题是你根本不会只用一个》
  - 《一处配置，22 个 agent 同步：我为什么用 Rust 写了个 AI agent 配置中枢》

**选题 2（技术科普 + 个人故事，塑造开源人设）**
- 角度：科普「MCP / skill 到底是什么、为什么每家 agent 各存一套」，讲清楚这个生态的碎片化，顺势引出可移植 Skills（.skill 包 + SHA-256 校验 + skills.sh 市场）和 keychain 存密钥。工具是科普的落点。
- 备选标题：
  - 《MCP、Skill、Provider 全给你讲明白：AI coding agent 的配置到底乱在哪》
  - 《我把 22 个 AI agent 的配置统一了，顺便搞懂了这套生态有多碎》
