## 原生语感（这里的人到底怎么说话、什么调性）

- 自称与互称是「佬」文化：管论坛叫「L 站 / 佬站」，管彼此叫「佬友」，热心分享的大佬叫「热佬」，求助开头常见「佬们 / 佬友们，求个…」。[检索所得——黑话 wiki 摘要 + 多个真实帖标题如「佬们都在用什么公益站」] 这是最快能让你「像本地人」的一层皮。
- 官方立社训是「真诚、友善、团结、专业」，社区把「禁 AI 灌水内容」「反算法/反标题党」当护城河。[检索所得——seekstar 转述官方核心价值] 直接后果：**说人话、少形容词、多干货**是这里的默认语感，堆排比和情绪词会立刻显假。
- 玩梗底色偏极客与自嘲：「始皇 / 祖师爷」（指 Linus）、「润」（跑路/离职/换环境）、「支棱起来了」（终于搞定了）、「喜获 xx 子域名」这类反讽式炫耀。[检索所得——真实帖标题「我也是支棱起来了，喜获 linuxdo 子域名」等] 用得对能拉近距离，用错就像老板在员工群发表情包。

## 什么内容能起量（越具体越好）

- **真·完整开源 + 解决自己真实痛点的小工具**。社区最认「我自己被这事烦到了，于是写了个东西」，代表帖如「感谢 Any 大善人，开发了一个能实实在在解决工作中的痛点的小工具」。[检索所得——https://linux.do/t/topic/2491216]
- **保姆级 / 喂饭级教程长文**。标题里直接写「[实践|教程|长文]」「保姆级喂饭版」「超级小白入门指南」，把安装、配置、踩坑一步步截图讲透，是开发调优板块的顶配。[检索所得——https://linux.do/t/topic/1537257 、https://linux.do/t/topic/777155]
- **围绕当红生态做增量**：Claude Code / MCP / AI coding agent 是当前绝对热点，「一键交互式配置工具，小白也能轻松上手」这类直接踩在痛点上。[检索所得——https://linux.do/t/topic/836692]
- **横向对比 / 聚合类**：「做了一个 X 在不同平台价格对比的网站」「总结一些有趣有用的 GitHub 开源项目」这类帮人省事的整理帖长期有流量。[检索所得——https://linux.do/t/topic/2264140 、https://linux.do/t/topic/116554]
- **真诚的过程叙事**：讲「为什么做、怎么取舍、踩了哪些坑」的建站/造轮子回顾，比纯功能罗列更容易被顶。社区有「宝藏贴周汇总」在持续打捞这类内容。[经验推断 + 检索所得周汇总帖存在]
- **回复即货币**：帖子靠回复顶起来，一个能引发「我也遇到过 / 我是这么解决的」讨论的帖，比自吹自擂的帖活得久。[经验推断——Discourse 机制 + 社区回复文化]

## 什么显 AI 味 / 显尬 / 显硬广（要避开的雷）

- **AI 腔本身就是原罪**。社区明令禁 AI 生成灌水，开源推广新规甚至要求「帖内 AI 生成/润色的部分要截图标注出来」。整篇一股 GPT 味（排比、「在当今…时代」「不仅…更是…」「让我们…」）会被一眼识破并鄙视。[检索所得——https://linux.do/t/topic/1776670 要求 AI 内容需截图声明]
- **引流其他社区 = 骑脸**。运营原话性质的规则：不得在本社区给另一个社区/社群/群引流，「此视为骑脸行为」；不再接受任何公开形式的 AFF（联盟链接），要 AFF 请私聊。往帖子里塞「加我微信 / 进群 / 关注公众号 / 我的知识星球」是硬雷。[检索所得——https://linux.do/t/topic/991874 、https://linux.do/t/topic/1776670]
- **不开源却来推广**。开源推广的门槛是「完整开源、无未开源部分、且项目里链接认可 LINUX DO」。半开源、只放个下载链接、闭源求 star，都会被质疑动机。[检索所得——开源推广新规四项要求]
- **标题党 / 纯求 star**。「[开源项目求 star]…（借号使用，留言不回复）」这种冷淡引流姿态口碑差；社区反感只索取不互动。[检索所得——https://linux.do/t/topic/780738 标题即透着这股味]
- **新号空降打广告**。信任等级低的新账号一上来就发推广，既容易被风控，也天然被怀疑是营销号。[检索所得——注册风控 + 信任等级机制]
- **过度包装的情绪营销**：「颠覆」「革命」「效率提升 10 倍」「再也不用…」这类词在这里减分。开发者更信「我实测省了大概多少次重复配置」。[经验推断]

## 格式与硬约束（篇幅、标题、标签、封面、结构、发布机制）

- **发布机制/门槛**（检索所得）：邀请制/审核注册；Discourse 信任等级 0→4。新号有风控，注册后短时间内发太短的内容容易被拦；等级靠阅读时长、进入话题数、获赞等自然攒。**含义：先养号、先在别人帖下真诚回复攒信任，再发自己的推广帖，成功率高得多。**
- **板块选择**（检索所得）：
  - `开发调优`：造轮子、工具、教程、技术问答的主场——aghub 首选。
  - `资源荟萃`：偏资源/项目聚合分享。
  - `福利羊毛`：抽奖、CDK、公益站、羊毛——**别把纯工具帖发这里**，除非真带福利。
  - `搞七捻三`：闲聊灌水区，可发轻松版的「造轮子心路」。
  - 板块是大类、**标签（tag）是细分**；推广必须打上官方要求的 `开源推广` 标签。[检索所得——板块=父类、标签=接口 的社区类比 + 开源推广需打标签]
- **标题范式**（检索所得，真实帖归纳）：爱用方括号前缀标注类型/属性，例如 `[实践|教程|长文]`、`[分享]`、`【保姆级喂饭版】`、`【开源推广】`。标题直白说清「这是什么 + 给谁用」，不玩虚的。
- **正文结构**（经验推断 + 教程帖惯例）：Markdown 原生支持。常见骨架 = 一句话背景痛点 → 「为什么做/现有方案的问题」→ 功能点（配图/GIF/终端截图）→ 安装使用步骤（可复制的代码块）→ 已知问题/roadmap → 开源地址 + 一句「欢迎佬友拍砖」。截图/GIF 几乎是标配，纯文字工具帖吃亏。
- **封面**：Discourse 会取正文首图作预览图，所以**第一张图放最能说明价值的截图/GIF**，别放 logo。[经验推断——Discourse 机制]

## 自我推广的容忍度与原生包装方式

**能推，但有明确的"正门"，走正门就完全不算广告。** [检索所得——存在官方「开源推广」通道]

- 正门就是官方的 **`开源推广`** 机制：只要①完整开源、②项目里链接并认可 LINUX DO、③打上 `开源推广` 标签、④把帖内 AI 生成/润色部分截图声明，就可以在公开版面光明正大地推。这等于社区给「自己做的开源工具」发了合规通行证。[检索所得——https://linux.do/t/topic/1776670]
- 原生包装的关键不是藏广告，而是**把重心从「我的产品多牛」挪到「我遇到的问题 + 我怎么解的 + 你可以直接拿去用」**。开发者视角的技术真心话（架构取舍、踩过的坑、为什么不用现成方案）本身就是这里最受欢迎的内容形态，产品只是这段真心话的自然落点。
- 具体动作：先给价值（教程/对比/踩坑）再给链接；开源地址放正文而非只在标题喊 star；结尾主动请人拍砖、明确说「有 bug / 想要啥功能开 issue 或回帖」，把帖子做成双向讨论而不是单向发布。
- 红线复述：**别引流到微信群/公众号/星球/其他论坛**，别放公开 AFF，别闭源来推。踩这三条，再好的工具也翻车。[检索所得——https://linux.do/t/topic/991874]

1. 「用了小半年 Claude Code、Codex、Cursor 一路换过来，最烦的就是每换一个 agent 就得把 MCP、skill、模型 key 重配一遍。忍不了了，用 Rust 撸了个东西把这几家的配置统一管起来，完整开源，先上来给佬友们拍砖。」

2. 「先说结论：一份 MCP 配置，一次填好，同步到你装的所有 AI coding agent，还能跨 agent 审计谁配了啥。这是我这两个月晚上下班后做的 aghub，Tauri + Rust，桌面端和 CLI 都有，下面把为什么做、怎么取舍讲清楚。」

3. 「【开源推广】受够了在 Claude / Cursor / Windsurf 里重复配置的佬友进来看看——aghub：22 个 AI coding agent 的配置中枢」

4. 「不是又一个 AI 套壳。我不碰模型，只解决一件事：让你手里那十几个 coding agent 的 MCP / skill / 模型 / key 只需要配一次。踩过的坑和目前还没搞定的地方也一并写在下面，别客气。」

## 真诚⇄炒作该落在第几档

**1 档（最真诚克制）。**

理由：这是本次所有目标平台里最该压低音量的一档。社区把「禁 AI 灌水 + 反标题党 + 真诚友善」当立身之本，任何一点炒作腔、情绪营销、引流动作都会被一眼看穿并反噬信任等级和口碑。这里的流量逻辑不是「喊得响」，而是「东西真、人真诚、愿意跟你讨论」。aghub 的独立开发者气质在这里是加分项——放大「我自己被这问题烦到了才做的」这条线，把产品藏在真心话后面，比任何 hook 都好使。（对照参考：小红书/公众号可到 3–4 档，L 站唯独要回到 1。）

## aghub 在这个平台的切入角度（1-2 个具体选题/标题）

**选题 A（主推，走开源推广正门 · 开发调优板块）**
- 标题：`【开源推广】一份 MCP 配置同步到所有 AI coding agent —— 我用 Rust 写了 aghub`
- 结构：开头讲「重度用多个 agent、受够重复配置」的真实痛点 → 现有做法为什么难受（各家格式不一、key 散落、没法跨 agent 审计）→ 核心能力配 GIF：统一管 MCP、可移植 Skills（.skill + SHA-256 校验 + skills.sh 市场）、BYOM（key 存 OS keychain）、每 agent 独立选模型、Usage 监控 → 安装步骤（CLI + 桌面端）→ 技术取舍：为什么 Rust + Tauri、支持 22+ agent 的适配器架构怎么设计的、踩过哪些坑 → 开源地址 + 认可 LINUX DO 的链接 + AI 润色部分截图声明 + 「欢迎拍砖/开 issue」。合规四要件一次凑齐。

**选题 B（技术真心话向 · 更适合先攒信任的养号期发）**
- 标题：`[长文] 给 22 个 AI coding agent 做统一配置层，我踩过的坑和几个架构取舍`
- 角度：几乎不谈"产品"，只谈工程——每家 agent 的配置格式差异（Claude 的 skill 不进 JSON、OpenCode 的 mcp 对象 key、Codex 的 TOML…）、如何用 descriptor/registry 驱动而不是给每家写死特例、跨 agent 审计怎么做、key 安全为什么走系统 keychain。把 aghub 作为「这套思路的落地实现」在文末自然带出。这类纯干货帖最符合「开发者视角的技术真心话」，容易被顶且几乎不触雷。
