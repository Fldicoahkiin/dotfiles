# 最高层：先有一个你真信的观点

比「说人话」还高一层。说人话管句子，这份管**整篇有没有一条主线**。

## 问题

AI 文章是把几个 section 拼起来：痛点 → 功能 → 对比 → 诚实边界 → 适合谁 → CTA。每个 section 单看都没错，但整篇背后没有一个作者真信的观点在贯穿。读起来就是「AI 生成」——顺、全、平，**没有人的意图**。

真人写东西是因为他有一个想让你信的观点。结构是这个观点在展开，每一段是它的证据或推论，不是清单上的下一项。

## 规则

写之前先定这一篇要让人信的**那一个观点**。然后：

- 结构 = 观点的展开。每一段自问：这是在推进那个观点，还是只是 section 清单里的下一格？
- 把每段的第一句连起来读，应该是**一条论证线**，不是几个并排的小标题。如果是后者，这篇没有主线，重写。
- **没有观点，先别写。** 硬凑出来的一定是拼装。

## 写前两道闸（过不了就别动笔）

**① 底料闸。** 打开 `products/<产品>.md`：有没有能撑一篇的真素材——具体数字、真实的设计取舍、能点名的符号、背得住的对比？**没有就拒绝写，先补料。** 写不出好开头，九成是内容本身没东西，不是措辞问题；空料硬写出来的只能是套话拼装。

**② 观点闸。** 把这篇想讲的 claim 全列出来，然后问：**只能留一件事，留哪个？** 其余的要么砍、要么降级成那一件事的证据。说了六件事等于什么都没说清。砍的时候改法要**具体到文字**——删哪段、哪句并进哪句，不是「加强重点」。

## 产品的观点住在底料里

每个产品「要说的那一件事」写在它自己的 `products/<产品>.md` 里，写哪个产品就用哪条当主线，不在这里集中放：

- aghub → 配置是你的（见 [products/aghub.md](products/aghub.md)）
- rust-rewrite → 护栏 > AI 魔法（见 [products/rust-rewrite.md](products/rust-rewrite.md)）

一篇稿从头到尾都在证那一件事，就有主线了。

## 删掉这些多余的套路段落（AI 拼装的标志）

- **「诚实讲还没搞定的 / 现在还不行的地方」义务清单**——最假。限制若跟论点相关，在行文里一句带过、且是自信的；绝不单开一节自我拆台来"显得平衡"。
- **「适合谁 / 谁不需要它」**——观点立住了，读者自己清楚。
- **「工具是我们仨做的 / 求轻喷 / 觉得有用给个 star」**——多余的收尾 CTA。（正式 launch 署名 @ 队友是另一回事，日常正文不挂。）
- **「痛点」式开场铺垫**——直接从观点或技术现状进。
- **「这是推测的 / 来源存疑 / 还没逐字验证」式的元标注**——站得住的判断就肯定地说。合理推断、非逐字来源但逻辑成立的结论，直接给结论，别预先给自己盖个「推测」的章。这种学术式免责在宣发和产品文档里只会显得心虚、削弱说服力。（底线还在：真没根据的别写——这是「把正确的肯定说出来」，不是「编」。跟上一条一脉：杀的是自我削弱的姿态，不是杀内容。）

## 一个区分：别把该留的也删了

「先有观点」杀的是**产品局限义务清单**，不是**对自己论断的诚实**。

- 保留（这是真人味）：对你说出口的技术判断诚实——「这几条是我翻源码和自己用下来的观察，哪家最近改了行为和我说的不一致，欢迎指正」。这是对**claim 的诚实**，织在论证里。
- 杀掉：「诚实讲还没搞定的：Windows experimental、有些 agent 支持不全」这种**产品 TODO 清单**当收尾。那是营销的平衡术，不是诚实。
