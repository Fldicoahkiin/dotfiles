# 微信公众号 · 平台卡（批量捞边际流量）

**档位**：语气 2.5 / 钩子 3.5（**正文 2 档真诚，标题摸到 3 档克制标题党**）　|　一个真人在跟你聊天，不是文档在朗读你。可复用博客长文改写。

## 铁律
- **把「我做了个工具」讲成「我遇到一个问题，忍不了，于是自己写了个东西解决它」**。工具是故事的结果，不是文章主语。
- **痛点前置**：先花 1/3 篇幅把「多 agent 反复配置」写透，读者点头「对对对」，工具出场时是救星不是广告。
- **开源人设兜底**：Rust + Tauri + 开源、key 进 keychain、「我自己每天在用」而非「你应该用」。
- **克制 CTA**：文末一句「代码在 GitHub，链接放阅读原文」即可，别通篇导流。

## 格式硬约束
- 订阅号每天仅 1 次群发（单次最多 8 篇）→ 攒够一波再发，别浪费当天唯一推送。
- 长文甜点区约 4500 字 ≈14 分钟；每段 ≤3 行；每 300-500 字一个小标题。
- 标题 15-32 字优先，至少改 5 版（分别强化数字/情绪/反差/产品名/读者利益）。微信在治理标题党，别夸大欺骗。
- 封面转发卡片取第一张图，3:4（1080×1440）最佳。
- 标「原创」获保护+推荐权重；转载/洗稿新号必死。
- **开头 120 字须做完三件事**：交代发生了什么 + 表达强烈情绪 + 抛出真问题。

## 长文结构模板
- 工具评测类：一个观点开局 → 用真实对比证它 → 工具是这个观点的落地 → 上手方法。（别单开「不足」「适合人群」小节——观点立住了读者自己清楚；限制要讲就一句带过）
- 痛点避坑类：痛点 → 常见误区 → 踩坑原因 → 判断标准 → 具体清单 → 互动结尾

## 钩子模板（aghub 版·前 120 字，可直接改用）
1. （痛点+自嘲）「我电脑里装了 7 个 AI coding agent：Claude Code、Cursor、Codex、Windsurf……上周加了一个新的 MCP server，然后发现——我得在这 7 个地方，把同一份配置手动抄 7 遍。抄到第 4 遍我停下来问自己：这活儿，2026 年了，真的还得人干吗？」
2. （数字+事件感）「22 个 AI coding agent，22 套配置文件，22 个存 API key 的地方。这是我做 aghub 之前，桌面的真实状态。三个月后它变成了：一处配置，全部同步。这篇讲讲中间遇到的问题，以及为什么最后我用 Rust 重写了它。」
3. （故事+强判断）「事情起因很蠢：我在 Cursor 里配好的一个 skill，想在 Claude Code 里也用，结果两边格式完全不通，得手动搬。那一刻我冒出一个判断——**AI agent 之间缺的不是能力，是一个『配置中枢』。** 于是我花三个月把它做出来了，开源，叫 aghub。」

## aghub 选题
- **A（横评上游+痛点·主推）**：站「全都用」的重度用户视角把「跨 agent 重复配置」写成公共议题。标题候选《装了 7 个 AI 编程工具后，我受够了把同一份配置抄 7 遍》《一处配置，22 个 agent 同步：我为什么用 Rust 写了个 AI agent 配置中枢》。
- **B（技术科普+个人故事·塑开源人设）**：科普「MCP/skill 到底是什么、为什么每家 agent 各存一套」，顺势引出可移植 Skills 和 keychain 存密钥。标题《MCP、Skill、Provider 全给你讲明白：AI coding agent 的配置到底乱在哪》。
