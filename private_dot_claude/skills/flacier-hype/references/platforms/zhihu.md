# 知乎 · 平台卡（批量捞边际流量）

**档位**：语气 2.5 / 钩子 3.5　|　懂行的人在给你讲清楚一件事。次要平台，靠「AI coding 工具怎么选/好用的 MCP」长尾夹带。总纲：「我不卖你东西，我把这件事讲透，你自己判断。」

## 铁律
- **靠内容价值带出产品，不直接推产品**。产品是「这个领域地图」上的一个点，不是文章主角。一篇 80% 篇幅夸自己 = 死。
- **开源、不接广告是最强护身符**，文中点明能大幅降低被当营销号的概率。
- **有个人痕迹**：要有「我用下来发现」的第一人称观察，纯搬文档参数会被判搬运号、权重低。宁可承认「我也没搞懂 X」，别硬吹装专家。

## 红线
- 别自问自答硬推（社区规则重点打击，限流/折叠）。
- 别通篇只有 aghub；别在评论区留「+V/加微信/私信领」（机器自动折叠）；别绝对化（史上最强/彻底解决/完美替代，也违广告法）。

## 格式硬约束
- 两条通道：**回答**（在别人问题下答，蹭现成流量池，首选）+ **专栏**（自控标题、可长文沉淀、便于外链收录）。
- 回答 1200-2000 字；横评/指南可万字但靠结构撑不是灌水。
- 标题 20-30 字、含 ≥1 数字、带 1-2 热门关键词/年份；三种钩子痛点/利益/悬念。典型 `年份 + 数字 + 主流工具名并列 + 到底选哪个/终极横评/完全指南`。
- 结构「提问-冲突-结论-举例-再阐述-总结」，横评题几乎必配一张「工具 × 维度」对比表，关键结论加粗。
- 收藏 > 赞（长文尤其）：内容要「值得收藏」（可复用清单、可照抄命令）。

## 包装梯度（从最安全到最激进）
1. **地图里的一个点**（最推荐）：写 AI coding 工具生态全景，客观测评一圈，讲到「跨 agent 配置同步」痛点时自然带出 aghub「顺便一提」。
2. **作者身份自然暴露**：讲透干货后末尾一句「这些坑是我做 aghub 踩出来的，GitHub 在 xxx，不感兴趣这篇干货照样够用」。
3. **教程夹带**：写通用 MCP 配置教程，只在「同时用好几个 agent 太麻烦」处把 aghub 列为可选方案（旁边也列手动方案显客观）。
4. **回答里克制引用**：在「有没有好用的 MCP 管理工具」下答，把 aghub 放进 5-6 个工具清单里，不吹第一，用「我在用的是」口气。

## 钩子模板（aghub 版，可直接改用）
1. （从格式差异切入）「我同时装了 Claude Code、Codex、Cursor 和 Windsurf。上周想给它们接同一个 MCP server，才发现四家存法都不一样——Claude 在 `~/.claude.json`，Codex 是 TOML，OpenCode 又自成一套。同一份配置我在四个工具里各写了一遍，还写错一个。跨 agent 管配置的真问题不在配，在每家都想按自己的方式存你的东西……」
2. （横评客观·回答最稳）「2026 年这几个 AI 编程工具，很多人是几个一起用，不是二选一。我把 Claude Code / Cursor / Codex / OpenCode 都当主力用了小半年，按补全/终端/插件/成本拉个表，最后说怎么按场景配。」

## aghub 选题
- **A（横评夹带·回答+专栏双发）**：《2026 我同时用了 6 个 AI 编程 Agent，最大的痛苦不是选谁，而是配置同步｜附我的解决方案》。70% 客观横评 + 对比表，论点落在「多 agent 用户的真痛点是重复配置」，末 15% 带出 aghub 并给纯手动替代方案显客观。
- **B（清单/教程·吃搜索长尾）**：《2026 好用的 MCP Server 我装了这些，以及怎么让一份配置在所有 agent 里同步（保姆级）》。前半推荐通用 MCP（可照抄命令），后半切「多 agent 怎么统一管」，aghub 作进阶方案。

## 反 AI 味 · 本平台专属雷
排比轰炸、「首先…其次…综上所述」空壳、每段「值得注意的是/总而言之」、形容词堆砌无实例——老用户对 GPT 味极其敏感。
