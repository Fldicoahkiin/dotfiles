# LinuxDo · 平台卡

**档位**：语气 1.5 / 钩子 2.5　|　全平台最该压低音量的一档。这里的流量逻辑不是「喊得响」，是「东西真、人真诚、愿意跟你讨论」。

## 铁律
- **说人话、少形容词、多干货**。社训「真诚、友善、团结、专业」，把「禁 AI 灌水 + 反标题党」当护城河。堆排比和情绪词立刻显假。
- **走「开源推广」正门就完全不算广告**。四要件：① 完整开源、② 项目里链接并认可 LINUX DO、③ 打 `开源推广` 标签、④ 帖内 AI 生成/润色部分截图声明。凑齐即可光明正大推。
- **重心放「我遇到的问题 + 我怎么解的 + 你可以直接拿去用」**，产品是这段技术真心话的自然落点。
- **先养号**：新号有风控，先在别人帖下真诚回复攒信任等级，再发推广，成功率高得多。

## 红线（踩了再好的工具也翻车）
- 引流微信群/公众号/星球/其他论坛 = 「骑脸行为」。别放公开 AFF。
- 不开源却来推广、半开源、纯求 star 冷淡引流。
- 「颠覆」「革命」「效率提升 10 倍」这类情绪营销词，这里减分。

## 格式硬约束
- 板块：`开发调优`（首选）。别把工具帖发 `福利羊毛`（除非真带福利）。
- 标题爱用方括号前缀标类型：`[实践|教程|长文]`、`[分享]`、`【开源推广】`。直白说清「是什么+给谁用」。
- Markdown 原生；截图/GIF 是标配，纯文字工具帖吃亏。Discourse 取正文首图作预览——**第一张图放最能说明价值的截图/GIF，别放 logo**。
- 回复即货币：能引发「我也遇到过/我是这么解的」讨论的帖活得久。

## 结构骨架
一句话背景痛点 → 为什么做/现有方案的问题 → 功能点（配图/GIF/终端截图）→ 安装使用步骤（可复制代码块）→ 已知问题/roadmap → 开源地址 + 认可 L 站的链接 + 一句「欢迎佬友拍砖」。

## 钩子模板（aghub 版，可直接改用）
1. 「用了小半年 Claude Code、Codex、Cursor 一路换过来，最烦的就是每换一个 agent 就得把 MCP、skill、模型 key 重配一遍。忍不了了，用 Rust 撸了个东西把这几家的配置统一管起来，完整开源，先上来给佬友们拍砖。」
2. 「我不碰模型，只解决一件事：手里那十几个 coding agent，MCP、skill、模型、key 只需要配一次，而且改了哪几项你自己看得见、随时能收回。下面讲讲各家格式的差异和几个取舍，欢迎拍砖。」

## aghub 选题
- **A（主推·走开源推广正门）**：`【开源推广】一份 MCP 配置同步到所有 AI coding agent —— 我用 Rust 写了 aghub`。结构见上，四要件一次凑齐。
- **B（养号期·技术真心话）**：`[长文] 给 22 个 AI coding agent 做统一配置层，我踩过的坑和几个架构取舍`。几乎不谈产品，只谈工程——各家配置格式差异（Claude 的 skill 不进 JSON、OpenCode 的 mcp 对象 key、Codex 的 TOML）、如何用 descriptor/registry 驱动而不是写死特例、key 为什么走系统 keychain。产品文末自然带出。最不触雷。

## 反 AI 味 · 本平台专属雷
「在当今…时代」「不仅…更是…」「让我们…」一眼被识破且被鄙视。AI 润色部分按规则要截图声明——干脆自己写，别润。
