# 备选标题（5 版）

1. 用了大半年 CC Switch，最后我还是自己写了一个
2. 一个替你切配置的工具，凭什么把你的 settings.json 整份重写
3. 配置是你的：我为什么放弃了托管式的 CC Switch，自己写了 aghub
4. 切 provider 那一下，它悄悄把我手写的东西冲掉了
5. 我不想再信谁替我保管配置，于是花时间写了 aghub

---

用了大半年 CC Switch，我最后还是自己写了一个。

切 provider 这件事它做得挺顺，点一下就换。让我停下来的是另一件事：有一次我在 shell 里 export 了几个环境变量，Claude Code 死活不认；查了半天才想明白——`settings.json` 现在归它写，我在 shell 里设的那些值，根本进不去。

那一刻我意识到，我其实已经不太拥有自己的配置了。

一个管配置的工具，对待你已经写好的那些文件，无非两种态度：接管，或者服务。选哪种，基本就决定了它是什么东西。

CC Switch 选的是接管。它把 provider 配置收进自己的一个数据库，以这份库为准，每次切换都拿库里的版本，把 `settings.json`、`config.toml` 整份重写一遍。你目录下那份配置文件，在它眼里只是一个被覆盖的输出。

## 接管之后，配置就不再是你的了

下面这几条，是我长期用下来一条条踩出来的，说给同样重度用多 agent 的人听。

shell 里设的环境变量作废。`settings.json` 归它写，Claude Code 只认它写进去的那份值，你在外面 export 的它不管。

你也看不清它到底改了什么。配置在它的库里，不是一份你能打开、能 `git diff` 的文本。这次切换动了哪几个字段，它不交代，你也没法查。

它还会盖掉你手写的东西。那些没进它库的 plugins、MCP、permissions——你自己手动加进 `settings.json` 的——下次切换，可能就没了。

退出也不干净。它第一次启动就把你的配置导进库，从那以后，真正生效的那份状态，就不在你自己的文件里了。

这些不是哪一版没写好。是它的取向决定的：配置存它的库，对外整份覆盖。取向本身自洽，喜欢的人自然有理由喜欢。只是它有个隐含前提——你得信它保管得住。我不想信这个。配置本来就是我的东西，我想自己拿着。

## 于是我写了 aghub

它从头到尾只认一件事：配置是你的，我帮你配好、配稳，不替你保管。

所以它增量编辑，不接管。它直接读你现有的配置文件，只改你明确指定的那几项，别的原样不动。它不写全局状态，不注册后台 handler，不驻留进程。每次改了什么，是一次能 `diff` 出来的文本变更。你把某一条删掉，对应的条目就没了，零残留。你目录下那份文件，从头到尾都是你的，它只是往里写了你让它写的那几行。

举个具体的。我让它给 Claude 配一个 MCP server，它就往你的配置里加那一个 server 的那几行，别的不碰。你在同一个文件里手写的 permissions、别的 server，它看都不看一眼。切别的 provider，它也只动 provider 那一段。想知道它干了什么，`git diff` 一下全在那儿。

BYOM 那块也是同一个取向。给 Claude、Codex、OpenCode 接自定义推理端点时，API key 存进系统原生的 keychain，不落到明文配置里。provider 预设从 models.dev 在线拉，不内置任何商业中转、不塞赞助条目——列表里有什么，就是 models.dev 上有什么。桌面端还会在检测到「记录的清单」和「实际写进文件的」对不上时，主动提示你同步，而不是背着你改。

## 连代码里都是这个原则

这套「不接管」不只是功能层面的一句承诺，它一路贯到实现。

aghub 现在支持 22+ 个 agent，格式各不相同。Claude 的 skill 不进 JSON，得去扫 `~/.claude/skills` 下的 SKILL.md；Codex 用 TOML，还只吃 stdio 的 MCP，远程的它不认；OpenCode 把 SSE 和 StreamableHttp 合并成 `"type":"remote"`，一趟 roundtrip 下来 transport 的身份就丢了。这些差异，每一个都是特例。

处理特例最省事的写法，是在主流程里到处塞 `if agent == "claude"`。我没这么干。每个 agent 是一张静态的 `AgentDescriptor`——它的解析、序列化、路径、能力声明，全是挂在这张描述符上的函数指针。加一个新 agent，就是加一个文件，再把它注册进 `ALL_AGENTS`，主流程一个字不用改。

这么写，是因为哪家 agent 哪天改了格式，我想一眼找到该改的地方、干净地改掉，不用在一坨分支里翻。对代码的这个要求，和对你配置文件的那个承诺，是同一件事：该动的精确地动，不该碰的一个字不碰。

底层三套接口——桌面 App、CLI、HTTP API——共用同一份 core。你在桌面上点的、在命令行里敲的，走的是同一套逻辑。

## 边界我也说清楚

上面那几条关于 CC Switch 的判断，是我翻它行为、自己长期用下来的观察。哪一条和它最近某个版本的实际行为对不上，欢迎指出来，我改。

aghub 是 Rust + Tauri 2 写的，开源，跨平台，我自己每天在用（Windows 还标着 experimental，有些问题在修）。如果你也同时开着好几个 agent，也想让自己的配置一直归自己，可以来试试。

代码在 GitHub（github.com/akarachen/aghub），链接放在阅读原文。
