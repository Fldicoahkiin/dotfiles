## 动态一 · 增量编辑

一个改你 `settings.json` 的工具，改完之后你能不能一眼看出它动了哪几行？我做 aghub 时给自己定的第一条规矩就是要能。

它读你现有的配置文件，只改你显式指定的那几项，别的一个字节不碰。所以加一个 MCP server，`git diff` 出来就是新增的那几行，孤零零的，其余原样。我自己 review 的时候一眼知道它做了什么，不用猜。

删也对称。删掉一个 MCP，它就把对应那几项从文件里拿走，`settings.json` 回到我没来之前的样子，零残留。它不写全局状态、不注册 handler、不在后台留进程，所以卸载不用满硬盘找它藏了什么。

配置从头到尾是你的文件，我只是帮你改那几行——这跟「把你配置收进我自己的库、以库为准、每次整份重写」是两种完全相反的态度。

## 动态二 · 预设从 models.dev 拉

给 Claude、Codex 接自定义模型端点这功能，不少工具会内置一份 provider 列表。点开看看里面装了什么——中转站、赞助条目，混在正经端点中间。

aghub 的预设是从 models.dev 在线拉的，不内置任何商业中转、不塞赞助。我不想要一个管配置的工具替我决定该走哪个中转，那是我自己的事。工具的活儿是把我选的那个端点配对格式、写进对的位置，不是往我眼前的列表里夹带它想让我看见的东西。

顺带说 key：接进来的 API key 不落明文，存系统的 keychain。工具经手你的密钥和你的选择，最低限度是别顺手加私货。

## 动态三 · 加一个 agent 是加一行

aghub 支持 22+ 个 agent，每家配置格式都不讲道理：Claude 的 skill 不进 JSON、得去扫 `~/.claude/skills` 的 SKILL.md；Codex 用 TOML、还只吃 stdio 的 MCP；OpenCode 把两种远程 transport 塌成一个 remote……这种特例只要往主流程里塞 if-else，加到第五家就没法维护了。

所以在 aghub 里每个 agent 是一张静态的 `AgentDescriptor`：解析、序列化、路径、能力声明，全挂成表上的函数指针。加一个新 agent，就是新写一个文件、把它注册进 `ALL_AGENTS` 这个数组，主流程一行不动。差异被收进一张能扫完的表，不是散在二十几处分支里。

这套写法约束的是我自己：哪天哪家 agent 改了配置格式，我得能一眼翻到它那张表、干净地改掉。对你的配置只动该动的那几项，对我的代码也只改该改的那一张表——是同一条原则。
