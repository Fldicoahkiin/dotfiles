## 正文

CC Switch 我用了大半年，一直有个地方不舒服，最近才想明白是什么。

它管 provider 配置的办法，是把这些配置收进它自己的一个数据库，以那份库为准。你每切一次，它就拿库里的版本，把 settings.json、config.toml 整份重写一遍。你目录下那份配置文件，在它那儿只是一个可以被盖掉的输出。

问题就出在这。切完之后，真正生效的东西不在你的文件里了，在它库里。

我在 shell 里设的环境变量不作数了，Claude Code 只认它写进 settings.json 的值。我想看它到底改了哪几个字段，也看不了，配置在库里，不是一份能打开、能 diff 的文本。我手写、没进它库的那些 plugins、MCP、permissions，下次切换可能就没了。第一次启动它就把配置导进库，从那一下起，你的文件就只是个副本。

这不是它哪一版没写好，是它一开始就选了托管：配置存我库里，对外整份盖过去。托管的意思就是，你得信它替你保管得住。我不太想信，我想自己拿着。

于是自己写了一个，叫 aghub，开源。就一条原则：配置是你的，我帮你配好，不替你保管。

它直接读你现有那份配置文件，你让改哪几项就改哪几项，别的一个字不动。不往全局塞状态，也不留后台常驻进程。每次改了什么，diff 一看就知道。哪天不想要了，删掉对应那几条就干净了，不留残渣。你的配置从头到尾归你，我只是替你动了指定的那几行。

顺手支持了 22+ 个 agent，Claude Code、Codex、Cursor、Copilot、Gemini、OpenCode 这些都在，所以你在哪个 agent 上都能这么拿回配置。CLI 和桌面 App 都有，Rust 写的。

想自己拿回配置的，GitHub 搜 akarachen/aghub。先收藏，哪天你也切烦了再来看。
