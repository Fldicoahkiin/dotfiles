## 二、旧思路残留：平台卡回退到 argument-spine / say-human 已经杀掉的套路

以下都是会**直接灌进成稿**的模板正文 / 结构骨架，与两条高层规则正面冲突。

### 2.1 「先说结论 / 先摆结论」开场（say-human.md:31 明令禁「开场提示层」）

- **`references/platforms/zhihu.md:28`** 钩子模板1：「……那晚我决定不能再这么活下去。**先说结论**，跨 agent 管配置目前有三种解法……」
- **`references/platforms/zhihu.md:29`** 钩子模板2：「**先摆结论**：2026 年这几个 AI 编程工具根本不在一个赛道上……」

  两条都是 say-human 黑名单原词「先说结论 / 先摆结论」，还被标成「可直接改用 · 回答最稳」，等于教用户写违禁开场。矛盾最直接。

### 2.2 「不是 X 而是 Y」二元对比假戏剧（say-human.md:33 明令删前半直接说 Y）

- **`references/platforms/linuxdo.md:27`** 钩子模板2：「**不是又一个 AI 套壳**。我不碰模型，只解决一件事……」——典型「不是 X，而是 Y」骨架，say-human 要求「多数删前半，直接说 Y」。
- **`references/platforms/zhihu.md:32`** 选题 A 标题：《2026 我同时用了 6 个 AI 编程 Agent，最大的痛苦**不是选谁，而是配置同步**》——同款二元对比，且会进成稿标题。

  （注：`aghub.md:42`「主线不是『重复配置好烦』，而是……」和 `aghub.md:53`「这不是实现缺陷，而是设计取向」也是这个句式，但那是 skill 内部描述主线的元话语、非成稿正文，从宽；不过既然 say-human 把此句式列为一眼假，元话语里也建议避开示范效应。）

### 2.3 表演式谦逊「还很糙 / 轻喷」（say-human.md:42 明令禁）

- **`references/platforms/jike.md:22`** 钩子模板3：「……支持 22 个 agent。**目前还很糙**，但『一次配 MCP……』这条主链路跑通了……」
- **`references/platforms/xiaoheihe.md:24`** 钩子模板3：「……讲讲我为什么做、它现在能干嘛、还差哪些。**轻喷**。」
- **`references/platforms/xiaoheihe.md:19`** 结构骨架：「……实测截图 + 主动说缺点 → 文末开源地址 + **轻喷**。」

  say-human 第 42 条原词点名「还很糙 / 轻喷 / 求轻喷」是表演式谦逊，「承认边界一句带过就够，姿态是自信的」。三处都把它写进了可直接复用的模板/骨架。

### 2.4 营销行话「踩过的坑 / 踩坑」泄进成稿（say-human.md:41 明令禁；黑名单第 21 行）

- **`references/platforms/linuxdo.md:27`** 钩子模板2：「**踩过的坑**和目前还没搞定的地方也一并写在下面……」——成稿正文里直接出现营销行话原词。
- **`references/platforms/zhihu.md:23`** 包装梯度2：「这些**坑**是我做 aghub **踩出来的**……」——成稿末尾句。

  这两处是写进成稿的正文。至于 `linuxdo.md:31`、`gongzhonghao.md:21/25`、`reddit.md:31/32`、`bilibili.md:22` 里的「踩过的坑 / 踩坑」出现在**结构说明和选题描述**（skill 元话语）里，危害小；但既然 say-human 把它定为「开发者不这么说话」的营销词，元话语里也宜换成「各家配置格式的差异 / 我遇到的具体问题」。

### 2.5 「适合谁 / 适用人群 / 不足」单列一节 + 收尾 CTA（argument-spine.md:29-34 明令删）

- **`references/platforms/gongzhonghao.md:20`** 长文结构模板（工具评测类）：「……优点 → **不足** → **适合人群** → 上手方法 → 互动结尾」。这正是 argument-spine 点名的两个「AI 拼装标志」：「不足」单开一节 = 产品 TODO 义务清单；「适合人群」= 「适合谁 / 谁不需要它」。整条结构骨架是旧的「痛点→功能→对比→诚实边界→适合谁→CTA」套路的翻版。
- **`references/platforms/xiaohongshu.md:26`** 结构骨架收尾：「适用人群 + 真诚一句『你们也试试』」——「适用人群」+ 收尾 CTA，两样都在 argument-spine 删除清单里。
- **`references/platforms/xiaohongshu.md:36`** 选题 A：正文末「免费开源，**评论区蹲需求**」；同段「你们也试试」——收尾求互动 CTA。

  argument-spine 立场是：观点立住了读者自己清楚，不用单开「适合谁」；「求 star / 觉得有用给个 star」是多余收尾 CTA。这几处平台卡还在把它当固定结构教。

### 2.6 「给个 star / 求 star」收尾

- **`references/platforms/bilibili.md:17`**：「『觉得**有用 GitHub 给个 star**，是对独立开发者最大的鼓励』比『记得三连』自然」——argument-spine.md:33 原词点名「觉得有用给个 star」是多余收尾 CTA。B站卡把它当推荐话术。（B站属正式 launch 场景可放宽，但与 argument-spine 的措辞正面撞车，至少该注明「仅正式 launch 视频，日常不挂」。）

## 三、平台卡之间 / 与上层规则互相矛盾

1. **痛点「永远从这里切」 vs 主线「不从重复配置切」——事实库自相矛盾**
   - `references/products/aghub.md:14`：「## 痛点（文案的入口，**永远从这里切**）」，随后整段讲的就是「重复配置好烦」。
   - `references/products/aghub.md:42`：「整波宣发的主线**不是**『重复配置好烦』，**而是**『用了大半年 CC Switch，最后我为什么还是自己写了 aghub』」。
   - 同一文件里，一处命令「永远从重复配置痛点切入」，另一处命令「主线不是重复配置烦」。两条对文案入口的指令直接打架，写手无所适从。需二选一或写清主次关系（如：日常动态从重复配置痛点切、集中宣发主线走 CC Switch 对比）。

2. **「痛点」作为文案入口 vs say-human 禁用「痛点」一词**
   - `say-human.md:21`+`say-human.md:41` 把「痛点」列为「做营销的人才说的词，开发者不这么说」，要求删。
   - 但 `aghub.md:14` 用「痛点」当正式小标题、`voice-dna.md:52` 收尾「具体的痛点」、多张平台卡卡头（xiaohongshu:3「具体痛点」、reddit 结构、douyin:7「痛点当主角」）都用「痛点」。
   - 这些多是 skill 元话语（讲方法论时用「痛点」指代一类东西），本身不进成稿，属可接受的术语用法。**但 say-human 的禁令措辞是「文案里出现痛点就删」，没有区分「成稿里禁 / 元话语里可用」**，导致规则自身读起来像在自打嘴巴。建议在 say-human 里点明：「痛点」作方法论术语可用，禁的是它出现在**成稿正文**里。否则审校时无法自洽。

3. **B站卡「11 个」既是用户装机数、又当成 aghub 支持数——口径混乱**
   - `references/platforms/bilibili.md:32`：「同步部署到我**全部 11 个** AI coding agent」、`:33`「我要手动改 **11 个**配置文件」、`:37` 选题标题「在 **11 个** AI 编程工具里重复配置」。
   - 事实库 `aghub.md` 全篇产品支持数是 **22+**。B站卡用「11 个」讲用户自己装了多少个还算合理叙事（没人真装 22 个），但 `bilibili.md:33` 模板2「同步部署到我全部 11 个 agent」把 11 说成 aghub 的部署覆盖面，与产品「推到全部 22+ agent」的卖点数字打架。跨平台看，用户装机数各卡不一（小红书 8、公众号 7、即刻/抖音 5、知乎 6、B站 11），单卡内自洽即可，但 B站这条把叙事数和产品能力数混成同一个「11」，读者会以为 aghub 只支持 11 个。建议 B站把「全部 11 个」改成「我装的这几个 / 我全部的 agent」，别坐实数字。

4. **xiaohongshu 钩子模板2 把「22 个」当用户装机数**
   - `references/platforms/xiaohongshu.md:30`：「我把 **22 个 AI 编程工具的配置**统一到了一个地方」。这里 22 是产品支持上限，但句子主语是「我把（我的）配置统一」，读起来像作者本人装了 22 个工具——与其它平台「用户装 5-8 个」的真实叙事不一致，也不可信（没人装 22 个）。要么改成「把我这几个工具的配置统一」，要么明确是「aghub 支持的 22 个」。
