### 00:00 - 00:15　钩子（直接屏录，不喊）

**分镜**：全屏终端。屏幕上摊着一份手写的 `settings.json`——里面有环境变量、几个 MCP、几条 permissions，一看就是人一行行敲的。光标在闪。不加任何片头。

**旁白**：
> 这是我手写的 Claude Code 配置。环境变量、几个 MCP、几条 permissions，都是我自己敲进去的。
> 现在我要往里加一个 MCP server。问题不在加不加得进去——在加完之后，这个工具还给不给我看，它到底改了什么。

**字幕**：
- 我手写的 settings.json
- 加一个 MCP
- 它改了什么，给不给我看

---

### 00:15 - 01:15　把这件事的矛盾摆清楚

**分镜**：真人半身出镜，屏幕另一半留着那份 settings.json。

**旁白**：
> 一个管配置的工具，对你已经写好的那些文件，其实只有两种做法。
> 一种是接管：它把配置收进自己的一个数据库，以库为准。你每次切换、每次改，它都拿库里那份，把你目录下的 settings.json、config.toml 整份重写一遍。你那份文件，在它眼里就是个被覆盖的输出。
> 另一种是增量编辑：它读你现在这份文件，只改你指定的那几项，其他一个字节不动。
> 听起来差别不大。可等你改完想检查一眼的时候，差别就全出来了。今天不讲概念，我直接改一次给你看。

**字幕**：
- 接管：配置进它的库，整份重写你的文件
- 增量：只改你指定的那几项
- 改完检查时，差别才出来

### 01:15 - 04:00　主段一 · 现场演示增量编辑

**分镜**：全屏终端，屏录，关键步骤不加速。

**旁白**：
> 先记住现在这份文件的样子。它在 git 里存着，`git status` 是干净的。
> 现在用 aghub 加一个 MCP server，一条命令。

**分镜**：敲 `aghub -a claude add mcp --name docs --command ...`，回车，返回成功。

**旁白**：
> 加完了。关键那一步来了——`git diff`。

**分镜**：敲 `git diff`，屏幕上只有几行绿色新增，红色删除是零。停在这一帧，给个特写高亮。

**旁白**：
> 你看这个 diff。整份文件里，它只加了这几行，就是我刚指定的那个 server。我原来的环境变量、其他 MCP、那几条 permissions，一行没动，连缩进和字段顺序都保持原样。
> 它没重排文件，没顺手改我别的东西。你能一眼看清它干了什么，因为它干的就是屏幕上这几行，没有别的。

**字幕**：
- git diff
- 只加了指定的那几行
- 其余零改动

**分镜**：接着演示删除。敲 `aghub -a claude delete mcp docs`，再 `git diff`。

**旁白**：
> 反过来，我把它删掉，再 diff 一次。
> 回到原样，零残留。文件跟我加它之前一模一样，`git status` 又干净了。
> 这就是增量编辑：进来只碰你让它碰的，走的时候不留痕迹。你的配置从头到尾还是你这份文件，不在别人的库里。

**字幕**：
- 删掉，再 diff
- 回到原样，零残留
- 配置一直是你这份文件

### 04:00 - 04:25　节奏切换（自嘲缓冲）

**旁白**：

**字幕**：

### 04:25 - 06:30　主段二 · 对照托管式

**分镜**：屏幕放一张示意图（讲原理，不点名截图）。左边画「你的 settings.json」，右边画「工具的数据库」，一根箭头从数据库指向文件，标「切换即整份重写」。

**旁白**：
> 托管是这么工作的。它第一次启动，就把你的配置导进它自己的数据库。从那一刻起，真正生效的那份状态，就不在你的文件里了，在它库里。
> 你每切一次 provider，它就拿库里的版本，把你的 settings.json、config.toml 整份重写。于是几件事跟着就来了。
> 你在 shell 里设的环境变量，不生效了——文件归它写，Claude Code 只认它写进去的值。
> 你想知道它这次改了哪些字段，做不到——配置在库里，不是一份能打开、能 diff 的文本。我刚才那个 diff，你在这儿没有。
> 你手写的、但没进它库的东西，某个 MCP、某条 permission、某个 plugin，下次切换可能就没了，因为它重写的时候只认库里有的。

**分镜**：切回终端，把刚才 aghub 那个只动几行的干净 diff 再闪一下做对照。

**旁白**：
> 我要说清楚，这不是它哪一版有 bug，是它选的做法就这样——配置存它的库，对外整份覆盖。这做法有它的道理，切换确实快、确实统一。
> 但代价是，你的配置不再是你手里那份文件了，你得信它保管得住。
> 我不想信这个。配置是我写的，我想自己拿着，想随时 diff 看它被改成什么样。所以 aghub 从头到尾只认一件事：配置是你的，我帮你配好、配稳，不替你保管。

**字幕**：
- 第一次启动就把配置导进库
- 环境变量作废
- 配置在库里，不能 diff
- 没进库的字段，切换可能丢
- 代价：配置不再是你手里那份文件

---

### 06:30 - 07:20　把这个取向落到代码里

**分镜**：屏录，打开 aghub 源码 `crates/core/src/agents/` 目录，鼠标划过一排 `.rs` 文件。

**旁白**：
> 这个「不接管」，连代码里都是一样的。
> aghub 现在管 22+ 个 agent，Claude Code、Codex、Cursor、Copilot、Gemini、OpenCode 这些，每家配置格式都不一样。它没把这些差异塞进一个大流程里用一堆 if 特判。
> 每个 agent 就是一张静态的 AgentDescriptor：怎么解析、怎么序列化、配置在哪个路径、支持哪些能力，都以函数指针挂在这张描述符上。要加一个新 agent，就是加一个文件、注册进 ALL_AGENTS 那张表，主流程一个字不改。
> 好处是，哪家 agent 哪次改了配置格式，我能一眼找到那张描述符，干净地改掉。对代码的要求，和对你配置文件的态度，是同一件事：边界清楚，改动能追溯，不往里塞看不见的东西。

**字幕**：
- 每个 agent = 一张 AgentDescriptor
- 加 agent = 加一个文件 + 注册进 ALL_AGENTS
- 主流程不塞特判

**分镜**：真人正脸。

**旁白**：
> 回到开头那个问题：改完配置，给不给你看它改了什么。
> 一个管配置的工具能不能让你 git diff、删了能不能零残留回到原样——一个连改了什么都不让你看的工具，你的配置就已经不完全在你手里了。
> aghub 是我们仨在做的，Rust 写的，开源，CLI 和桌面端都有。链接放简介了，你要是也想让配置一直攥在自己手里，去翻翻源码，自己 diff 一遍就知道我说的是真是假。

**字幕**：
- 不让你看它改了什么，配置就不完全在你手里
- github.com/akarachen/aghub
